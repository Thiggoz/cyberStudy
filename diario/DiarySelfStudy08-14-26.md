## ***Client-Server Basics***
- I started understanding how the **Client-Server Model** works, the room gives an example of a Pizza delivery to explain this model, where the client is a woman called "Alice", the server is the pizzeria called "Luigi's Pizzeria" and the protocol that allows communication between Client and Server is a man called "Bob". The room says that when the pizza is ordered the client sends a message (**Request**) to the server requesting a type of pizza, and the server sends another message (**Response**) to the client that says if the request is valid and if it's confirmed. The room also explains the **ports** system that is the identification system used to different services, for example, when Luigi's (server) offers multiple services, such as takeaway, dining in, and delivery. Each service uses a different door: door A for takeaway, door B for the restaurant, and door C for delivery, for that the client needs to use a different port for each service. The DNS concept is also explained in the room, DNS is the protocol that gives the server address for the client, that works like a GPS in real life, the client (Alice) searches for the server url (Luigi's Pizzeria) and the DNS gives the address (called **Internet Protocol IP**) to the client to establish a connection with the server using another protocol.

- Once the Client-Server Model is understood the room started an explanation of **Hypertext Transfer Protocol Secure (HTTPS)** introducing the **Request Methods** with a demonstration of the **GET** method on the lab machine.
> *GET Method* - Is basically used to retrieve a resource from a web server.
The room gives an example using a URL from THM and explains that the client doesn't need to specify the used method and that the browser already does this for the client, the server returns a response including the status code and the requested information for the client.
- After the GET Method explanation the room introduces some exercises on the lab machine, explains the terms *Scheme*, *Host*, *FileName*, *Address* and *Status*, and going to the page *"https://www.iamlearning.thm/contact"* to see the details of Scheme and Host, finishing up the room of Client-Server Basics module.
## ***Virtualization Basics***

- The explanation of that room starts with a simple example inserted, a building with 10 apartments where the building represents a server and a tenant is living alone in it simulating an application, but in the building the alone person needs to take care of all the needs of the building alone, including water, electricity, cleaning and security, making the work expensive, inefficient, and unnecessary for their needs, the room also shows another building with the same 10 apartments, but now with 10 tenants living there each one with their respective responsibilities, dividing the work and organizing everything with privacy, transforming a space that previously saw only 10% utilization into one operating at 100% of its total capacity, and now with a "Building Manager" that is called **Hypervisor**, the entity that allocates space, manages operations, and fosters harmony among the building's tenants.
- The Index ends with this:
> The building is the physical server
The apartments are the lab machines
The tenants are the applications or operating systems
And the building manager is the hypervisor (the software that was shown in greater detail later).

- After this, the room presents an explanation about the **Hypervisor**, basically the Hypervisor is the core technology of virtualization and is the software that:
> Divides a physical computer into multiple virtual ones.
Gives each lab machine its own share of CPU, memory, and storage.
Keeps everything isolated and safe.
Manages the lifecycle of lab machines (start, stop, pause, clone, delete).

- There are two types of Hypervisor:
**Type 1**: hypervisors run directly on the physical hardware, making them fast, efficient, and ideal for servers and professional environments.
**Type 2**: hypervisors run within an existing operating system, making them easier to install and ideal for learning, testing, or small setups.
The two types are used for different situations of use, like *Test Malicious Files*, *Production Server*, *Database Server*, *Software Testing*, *Kali Linux* and *Data Center*.
- Continuing with the explanation the room talks about the **Lab Machines (The Apartments of the building)**. In simple concepts, a **Lab Machine** (*Virtual Machine*) is a virtual computer created by the hypervisor, it has its own virtual CPU, RAM, storage, and network, can run any operating system (Windows, Linux, etc.) and it's completely isolated from other VMs. This means that if one VM breaks, the others continue to work.

- The last concept was **Containers (The rooms inside the Apartment)** that is basically a lightweight, isolated environment that runs a single application and all the necessary components to support it, they package the application and its dependencies (libraries, tools, versions), share the host's operating system, so they start almost instantly, remain isolated from each other, so a misbehaving container doesn't affect the others and they can run consistently on any machine, making them perfect for development, testing, and scalable deployments. The room ends the content saying that the VMs provide the "full apartment" with maximum separation and flexibility, while containers offer lightweight "rooms" ideal for scalable, fast-deploying applications.
